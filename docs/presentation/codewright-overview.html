Technical and management overview

Codewright

An AI software team you can steer: it asks first, works in steps, checks itself, and waits for your approval.

Runs on a 9B open model · everything executes in an isolated sandbox

The problem

Most AI coding tools are hard to trust

They guess

One vague request goes straight to code. Nobody asks which language, platform or features you meant.

They run unchecked

The code is written and handed over. Tests, lint and secrets are your problem, and a green result can still be wrong.

They are a black box

You cannot see who did what, how long it took, or what it cost, and you cannot stop it at the right moment.

The idea

Code decides what runs next. The model only fills in one step.

1

A fixed workflow

Each task type is a graph of named steps: plan, build, verify, review, deliver.

2

A small model

A 9B open model answers one bounded question per step, in a schema that code validates.

3

Humans at the gates

The run pauses for approval. You approve, edit or reject, and it resumes from where it stopped.

Guardrails

About ten, in four layers

Before work starts

Unsupported-language rule · questions with defaults · Confirm card · risk tiers 0 to 3

While a step runs

Schema-checked output · tool allowlists · model-call limits · token and time budgets · model-outage recovery

Checking the result

Tests and lint must pass · 5-try fix loop · secret scan · test code kept out of app source · approval gates

Containing damage

Docker sandbox · egress allowlist gateway · localhost-only previews · 4 session cap · workspace-locked file tools

Not yet: a judge that checks the result against the original request (next slides).

Why we run evals

The live run found real bugs, now fixed

Routing: "Make a to-do list app" was treated as a feature on an existing project and never asked for a language.

Sandbox sessions: all 4 were held for 2 hours, so the fifth app failed. The longest-idle one is now released.

Blank page: the model wrote test code into app source, which a browser cannot load. Verify now flags it.

False green: "0 tests passed" and a template with no calculator in it both read as success. Both are now failures.

Limits and next steps

What we know is missing

Known limits

  • A 9B model fails many algorithm tests (9 of 20)
  • React builds sometimes put JSX in plain .js files
  • Nothing checks the app against the original request
  • Mixed requests are not split into steps yet

Next

  • An acceptance guardrail: criteria from the requirements, checked against the built app
  • A planner for mixed requests
  • A stronger fix loop for TypeScript and JavaScript
  • Nightly evals with the live model

Where this leaves us

A controlled AI team that is honest about where it fails

For the team: a model that is stronger at routing and rules than at writing algorithms, with every failure visible.

For managers: a decision on a stronger model or hosting, and on building the acceptance guardrail next.
