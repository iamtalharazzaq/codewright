## What you get

- `backend/`: Go (net/http) + PostgreSQL (pgx), with sign-up and sign-in (hashed passwords, signed tokens), items that belong to their owner,
  and an admin-only user list (the first user to register is the admin)
- `frontend/`: Next.js (TypeScript): a sign-in form, the items list, an admin section; `/api/*` is forwarded to the backend
- `docker-compose.yml`: PostgreSQL, the backend and the frontend

## Run it with Docker

```bash
cp .env.example .env            # then set SECRET_KEY (openssl rand -hex 32)
docker compose up --build       # app: http://localhost:3000, API: http://localhost:{{port}}/health
```

## Run it for development

```bash
docker compose up -d db         # just the database (or leave DATABASE_URL unset: the backend then keeps data in memory)
# backend
cd backend && go run ./cmd/api
# frontend, in a second terminal
cd frontend && npm install && npm run dev       # http://localhost:3000
```

Set `DATABASE_URL=postgresql://app:app@localhost:5432/app` for the backend when using the database from Compose
(publish its port with `ports: ["5432:5432"]` first).

## Test it

```bash
cd backend && go vet ./... && go test ./...
cd frontend && npm install && npm test && npm run typecheck
```

## Where things are

- `backend/cmd/api/main.go`: starts the server
- `backend/internal/api/`: the routes and sign-in checks
- `backend/internal/store/`: users and items, in memory and in PostgreSQL
- `backend/internal/auth/`: password hashing and tokens
- `frontend/src/lib/api.ts`: the typed client for the backend (with its test)
- `frontend/src/components/App.tsx`: the screens

## API

| Method and path | What it does |
|---|---|
| `GET /health` | liveness check |
| `POST /api/auth/register`, `POST /api/auth/login` | `{email, password}` → `{token, user}` |
| `GET /api/me` | the signed-in user (send `Authorization: Bearer <token>`) |
| `GET/POST /api/items`, `PUT/DELETE /api/items/{id}` | the signed-in user's items |
| `GET /api/admin/users` | all users (admin only) |
